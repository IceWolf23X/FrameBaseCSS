# FrameBaseCSS code index

Compact technical map of the project. Paths are relative to the repository
root.

## Sources

| Path | Role | Content and relationships |
| --- | --- | --- |
| `framebase.css` | Canonical source and public contract | MIT-licensed, runtime-dependency-free monospace design system with a dark default theme. Defines `--fb-*` tokens, `.fb-*` layouts and components, and `.u-*` utilities under one namespaced contract. It is consumed directly by the documentation and imported by the light theme. |
| `framebase.min.css` | Generated distribution | Minified form of `framebase.css`. Generated by `scripts/build-css.mjs`; never edited directly. |
| `framebase-light.css` | Official theme override | MIT-licensed theme entry point that imports `framebase.css` and redefines only the color scheme, semantic palette, and shadows. It does not duplicate component or layout rules. |
| `framebase-light.min.css` | Generated distribution | Minified form of `framebase-light.css`. Its generated import targets `framebase.min.css`, while the readable source continues to target `framebase.css`. |
| `framebase-theme-template.css` | Editable theme starter | Valid standalone entry-point template that imports `framebase.css` and exposes the complete public root-token groups with guidance for palette contrast and stronger-contrast preferences. It intentionally has no generated minified counterpart. |
| `framebase-highlight.css` | Optional third-party integration theme | Complete MIT-licensed addon that maps FrameBaseCSS visual tokens to the documented Highlight.js `.hljs-*` output scopes. It requires a FrameBaseCSS theme and a user-provided Highlight.js build; no JavaScript is bundled or imported. |
| `framebase-highlight.min.css` | Generated distribution | Minified form of the optional Highlight.js theme, generated from `framebase-highlight.css`. |
| `index.html` | GitHub Pages homepage and dark verification | Public static entry point using `framebase.css` plus the optional highlight addon. Documents public HTML contracts and renders the same components in realistic public-site, dashboard, editorial, form, data, code, media, and responsive technical-documentation examples. It pins Highlight.js 11.11.1 for live syntax verification, includes a real highlighted-versus-plain comparison, and degrades to readable plain code without JavaScript. |
| `framebase-light-demo.html` | Manual light verification | Structurally identical copy of `index.html`; only the `framebase-light.css` link and reciprocal switch back to the dark theme differ. Components and the highlighted-versus-plain comparison contain no theme-specific markup. |
| `scripts/build-css.mjs` | Maintainer build entry point | Uses the pinned `clean-css` API to minify the three fixed distribution stylesheets and validate the editable custom-theme template without generating an output for it. Validates parser errors, warnings, MIT banners, and canonical imports before writing; `--check` compares committed outputs without mutation. |
| `package.json` | Build manifest | Defines the deterministic `build:css` and `check:css` commands and pins the sole direct development dependency, `clean-css`. Runtime consumers do not use this manifest. |
| `package-lock.json` | Dependency lock | Reproducibly locks `clean-css` and its `source-map` dependency for local and CI maintainer builds. |
| `.github/workflows/css-distribution.yml` | Continuous integration | Uses read-only repository permissions, Node.js 22, `npm ci`, and `npm run check:css` to reject missing or stale minified assets on pushes and pull requests. |
| `.nojekyll` | GitHub Pages configuration | Disables Jekyll transforms and publishes the static assets in the root of `main` directly. |
| `.gitignore` | Local tooling exclusions | Excludes `node_modules/` and npm debug logs while keeping generated distribution files versioned. |
| `README.md` | Public entry point | Describes the goals, quick start, official themes, optional Highlight.js integration, maintainer build, documentation path, customization model, browser requirements, licensing, optional attribution, and public file map. |
| `LICENSE` | Public legal contract | Standard MIT License granting permissive reuse while requiring preservation of the copyright and license notice. |

## `framebase.css` structure

1. Design tokens.
2. Reset, inheritance, and document base.
3. Typography.
4. General layouts.
5. Site shell and navigation.
6. Public pages.
7. Documentation layouts.
8. Content and action components.
9. Forms and native HTML controls.
10. Feedback, data, code, and media.
11. Secondary navigation and utilities.
12. Responsive behavior, user preferences, and print.

## Exclusions

The index intentionally excludes `.git/`, `node_modules/`, npm debug logs, and
other local caches. The three generated `.min.css` files remain indexed because
they are public distribution contracts. The repository contains no vendored
third-party source tree or binary asset; demonstration SVGs remain embedded in
the HTML to preserve offline rendering.
